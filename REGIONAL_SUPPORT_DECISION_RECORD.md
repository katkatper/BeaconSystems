# Regional architecture and support decision record

No national release is authorized until every decision has an owner, date and evidence.

| Decision | Required choice/evidence | Status |
|---|---|---|
| Primary and recovery regions | Threats, agency/residency constraints, latency | Pending |
| Failure model | Zone, region, provider and communications outages | Pending |
| Data replication | Encryption, consistency, RPO, transfer authority | Pending |
| Failover/failback | Trigger, authority, DNS/session/queue behavior, exercise | Pending |
| Capacity scaling | Thresholds, quotas, database/worker/storage scaling | Pending |
| Service levels | Availability, response, RTO/RPO and exclusions | Pending |
| Support coverage | Hours, on-call staffing, severity and escalation | Pending |
| Agency communications | Maintenance, incident, breach and recovery contacts | Pending |
| Cost controls | Budget alerts, tenant attribution and forecast approval | Pending |

Multi-region processing is not enabled merely because the application is stateless.
Privacy/Legal, Security, Operations and affected agencies approve data movement.
